## 2. Confirmed attack surface (recon results)

### 2.1 Identity platform — identityhomolog.acesso.io (reachable, no CF block)
- OIDC discovery: `/oauth2/authorize`, `/oauth2/token`, `/api/oauth2/tokeninfo` (introspection), JWKS.
- Token endpoint accepts: `client_secret_basic`, `client_secret_post`, `none`, and
  **JWT bearer** (`urn:ietf:params:oauth:grant-type:jwt-bearer`) + client assertion.
- Signin is multi-tenant: `POST /signin` with `_csrf` + `tenant_id` → tenant lookup.
- JWKS: single RS256 key (kid `7fba47dd-62b7-49ec-adad-eeb8c1588ac0`), x5c cert **expired 2022** (observation, core-ineligible standalone).
- **Unlocked by:** a tenant (companies use `tenant_id`) + credentials. Credentials come
  from Unico (service account) or a test account in the homolog tenant.

### 2.2 Web & SDK API — api.idcloud.uat.unico.app (reachable)
- `POST /client/v1/process` → `403 RBAC: access denied` without token (auth enforced).
- `GET /swagger` → Cloudflare block (they defend swagger paths — do not bypass).
- Other paths → 500 Apigee `RouteFailed`.
- **Unlocked by:** OAuth2 Bearer token (JWT-bearer grant, needs service account).

### 2.3 API contract — api.id.uat.unico.app (reachable)
- `/health` → `Healthy` (200).
- Everything else 404 without `Authorization` + `APIKEY` headers.

### 2.4 SDK backend — backend-sdk.uat.private.unico.run (reachable, Apigee)
- `POST /sdk/data-collect/submit` → `401 {"body":{"desc":"Invalid token"}}` (auth enforced).
- `POST /sdk/flags` (with Token/Project-Name/Project-Version/Platform) → 500 internal
  (endpoint exists, expects valid session).
- CORS header inventory reveals the full anti-fraud surface:
  `Token, Token-Shuri, Gen-Uuid, Sdk-Key, Api-Key, Sdk-Session-Id, Local-URL, Extra-Data, Extra-Value, Info, Dependencies, Print-Json-Dev`

### 2.5 SDK S web app — sdk-s.uat.private.unico.run (reachable)
- React SPA bundle `/static/js/main.56db8d43.js` (3.6 MB, includes TensorFlow.js).
- Build config: `BACKEND_BASE_URL=https://backend-sdk.uat.private.unico.run`,
  `ENV_CONFIGURED=UAT`, `ENDPOINT_CRYPTO_KEY=""`, `ENDPOINT_CRYPTO_IV=""` — **verified
  NOT a bug**: encryption material is generated per-request at runtime
  (`signatureProperties`/`saltProperties`, `decryptData(body.dataValue, sig, salt)`).

### 2.6 Web SDK (npm `unico-webframe` 3.26.2) — public source
- Capture frame: camera opening, TF.js face models (on-device analysis), Dorothy liveness plugin.
- Submission pattern (from bundle):
  ```
  headers = { Token, "Token-Shuri", "Extra-Value" (encrypted) }
  GET/POST to BACKEND_BASE_URL; response body { dataValue, signature, salt } — encrypted envelope
  ```

## 3. The test surface that maps to the program matrices

The program rewards **liveness bypass** and **processing/data-flow integrity breaks**.
The web SDK runs the liveness decision **client-side** (TF.js + Dorothy plugin in the
browser), then submits the result inside an encrypted envelope with session-bound
tokens. That makes the interception points:

| Matrix | What to test | Where |
|---|---|---|
| Photo / Video / 3D / Deepfake | Present fake to camera; engine must reject | sdk-h1.unico.io web SDK (browser) or mobile apps |
| Memory Manipulation | Tamper engine params / client result before submit | Intercept between iframe and backend-sdk |
| Template Injection | Inject artificial template/result into envelope | Re-encrypt envelope with own session key |
| Timing Attack | Race the process/token sequence | createprocess → capture → submit |
| Capture Relay | Replay captured envelope across sessions | Token-Shuri / Sdk-Session-Id reuse |
| Stream Manipulation | Modify camera stream (virtual cam) | Client side |
| Session Hijacking | Copy session state between instances | Token + Token-Shuri reuse |

## 5. Device-side runbook (the only steps that need hardware)

**Blocked from server environment:** `sdk-h1.unico.io` is behind a Cloudflare managed
challenge (all requests from datacenter IPs → 403 "Just a moment…"). The capture flow
requires a browser with camera (web) or a physical Android/iOS device (mobile — emulators
explicitly banned by the program).

### Web (zero cost)
1. Open `https://sdk-h1.unico.io/` in Chrome/Edge/Firefox/Safari with camera.
2. Run the capture flow once normally → record Transaction ID + Process ID (REQUIRED in report).
3. Photo attack: print a high-quality face photo, present at the camera, 100 attempts.
   Report if accepted >1%.
4. Video replay: 3+ different pre-recorded face videos on a second screen/device.
   Report if accepted on 3+ samples.
5. Interception (stream manipulation): run a local proxy (mitmproxy) or DevTools
   request blocking; tamper with the encrypted envelope fields (`Extra-Value`,
   `Token-Shuri`, `Sdk-Session-Id`) and observe backend response codes.
6. Every attempt: capture sample ID, result, Transaction ID, Process ID.

### Mobile
1. Download the **Android Native / iOS Native** app from `sdk-h1.unico.io/mobile-sdks`
   (preferred over Flutter; native = direct SDK integration). Physical device only.
2. Apps have a **30-day TTL** — if expired/error, re-download latest build.
3. Same presentation attacks; report must include Transaction ID + Process ID.

## 5. Report requirements (from program policy)

- Report MUST include **Transaction ID** and **Process ID** of the capture.
- Severity via **OWASP Risk Rating calculator**.
- Only report when matrix thresholds are exceeded:
  Photo >1% / 100 · Video 3+ samples · 3D mask >5% · Deepfake real-time <500ms ·
  Memory persistence across restarts · Template multiple formats ·
  Timing >50% reproducible · Relay across sessions · Stream undetected · Session copyable.
- Testing focus is the **SDK engine**, not the wrapper/test apps (wrappers OOS).
- All requests carry `X-HackerOne-Research: bug_assembly` and `User-Agent: bug_assembly`.

## 7. Credentials needed to unlock deeper API testing (request from Unico)

To test the API contracts (`api.idcloud.uat.unico.app` / `api.id.uat.unico.app`) and the
IDP properly, you need a **UAT service account** from Unico (docs: contact Unico support,
provide account name ≤12 chars + responsible person details):
- account name + tenant ID + base JWT payload + `.pem` private key
- Then: `POST https://identityhomolog.acesso.io/oauth2/token` with
  `grant_type=urn:ietf:params:oauth:grant-type:jwt-bearer` + signed assertion
  (iss `<account>@<tenant>.iam.acesso.io`, aud identityhomolog host, scope `*`, exp ≤ iat+3600).
- APIKEY for the API contract is separate (also from Unico).

With a token you can test: process creation, result/selfie/evidence retrieval, IDOR
between tenants, `Token-Shuri` replay, and the tokeninfo introspection endpoint.
